# env-uv: the network and files for Atmos, over libuv

Plan for the repository `ia-atmos/env-uv`, session `uv`.
Written in the session that maintains the compiler (`ia-atmos/lang`).

## Context

- An environment connects an Atmos program to the outside world: it
  runs the loop of a library, turns its input into events, and offers
  its operations as functions. In this implementation it is a file in
  Atmos with C in native literals, brought in with `include`.
- This one is for what is not a game: the network, files, and timers,
  over libuv, which runs the same on Linux, the Mac, and Windows.
- The interest for the language: a connection is a resource with a
  life, and a protocol is a sequence in time. Both are what structured
  concurrency is for: a task per connection, whose abortion closes it.
- The compiler is `ia-atmos/lang`, branch `main`. Read `doc/manual.md`
  there before writing code: "Environments", "Native Literals",
  "Native", "Include", "Pin".

## Design

- **A handle is a native value with a finalizer.** A `pin` gives it
  the life of its block: when a task is aborted, its connections
  close. Libuv closes in two steps (`uv_close`, then a callback): the
  memory of a handle is released in the callback, never in the
  finalizer itself, and the loop must run until the callbacks of the
  closes are done before the program ends.
- **An operation that waits is a task, or a function that awaits**:
  `await uv.tcp.connect(...)`, `val line = await uv.stream.line(s)`.
  A callback of libuv becomes an event to the program, which the
  operation awaits. An operation that is aborted cancels its request
  where libuv allows it.
- **An error is a throw**, with the name that libuv gives it. A
  connection closed by the other side is not an error of the program:
  decide whether it ends the read with `nil` or with an event, and
  use one rule everywhere.
- **Time**: the time of the program follows the clock of libuv, so
  that `await 1s` works with no timer of libuv written by hand.
- **Names of the events**: with a prefix (`:uv.read`, `:uv.close`),
  as `lib/sdl.atm` and `raylib.atm`. The convention across all
  environments is an open decision of the author: write the tags in
  one place.

What a server may look like (a sketch, not compiled):

```
task Client (s) {
    loop {
        val line = await uv.stream.line(s)      ;; nil when it closes
        until line == nil
        await uv.stream.write(s, line ++ "\n")
    }
}

pin srv = uv.tcp.listen("0.0.0.0", 7000)
pin cs  = tasks()
loop {
    pin s = await uv.tcp.accept(srv)
    spawn @cs Client(s)         ;; a connection lives with its task
}
```

The last lines show the question that the design must answer first: a
connection accepted in the body of a loop cannot be pinned there and
live in a pool outside. Find the form that the rules of `pin` allow
(the task accepts its own connection; the connection is not pinned
and lives by its references), and say which.

## Fidelity

- **Tests with no network outside**: the client and the server run in
  one program, on the loopback, and print a trace. Fixed ports are a
  source of failures: bind to port 0 and read the port.
- **Determinism**: the order of the events of two connections is not
  fixed. A test asserts what is fixed (the bytes of each connection,
  in order) and nothing else.
- **The address sanitizer** (`ATMOS_ASAN=1`) on every test: the two
  steps of the close are where the leaks and the uses after free are.
- **Abortion**: for each operation, a test that aborts the task in the
  middle and checks that the handle is closed and nothing is left.

## What the other ports taught

Read "What the Pingus port taught" in `ia-atmos/lang`,
`.claude/plans/261111-snkrx.md`. For an environment in particular:

- **A native literal fails by assigning to `st`**:
  `` `if (r < 0) { st = a_error("%s", uv_strerror(r)); }` ``. Never
  `return` out of one.
- **The names with the prefixes `a_`, `A_`, and `atm_` are
  reserved.** Give every name of the prelude a prefix of your own.
- **At the end**: `atm_stop()`, then `atm_quit()` (the finalizers
  run), then run the loop until the closes are done, then
  `uv_loop_close`.
- **A task spawned in the body of a loop, of an `if`, or of a branch
  of `match` is aborted when that block ends.** What lives longer goes
  to a pool of its owner, or is pinned outside:
  `pin t = if c { spawn T() }`.
- **A pinned value cannot be stored in a table of a module, nor in a
  table that is an argument.** Design the functions so that handles
  are plain arguments.
- **The time passes in pieces**: a `:clock` await awakes at each timer
  that expires.

## What the port may need from the compiler

Report to the session of the compiler, with a small program:

- An emit from C to one task (the callback of a request awakes the
  task that made it), and its cost against a broadcast with a filter.
- A finalizer that cannot finish at once (the close in two steps).
- The rules of `pin` against a connection that is accepted in one
  block and lives in a task of a pool.

## Risks

- **Two environments in one program.** A program has one `main`. A
  GUI with the network needs the loop of the GUI and the loop of
  libuv. The step function is a first answer; the design is the
  author's, with `env-iup`.
- **The close in two steps** against finalizers that run at once.
- **Other systems.** The container is Linux. The Mac and Windows are
  the reason to choose libuv, and are not tested here: say so in the
  readme.
