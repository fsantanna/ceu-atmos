# env-sdl: one SDL environment for Atmos

Plan for the repository `ia-atmos/env-sdl`, session `env-sdl`.
Written in the session that maintains the compiler (`ia-atmos/lang`).

## Context

- An environment connects an Atmos program to the outside world: it
  runs the loop of a library, turns its input into events, and offers
  its operations as functions. In this implementation it is a file in
  Atmos with C in native literals, brought in with `include`.
- The organization names its repositories `env-<library>` for an
  environment and `<library>-<project>` for a project over it. There
  are `env-pico` and `env-ray`. There is no `env-sdl`: this repository
  is to be it.
- Three games were ported over SDL2, and each wrote a platform layer
  of its own. The author asked that they use the environment they are
  supposed to use, instead of custom engines.
- So the work has two parts: write the environment, from what exists;
  then help each game move to it, with its tests identical.
- The compiler is `ia-atmos/lang`, branch `main`. Read `doc/manual.md`
  there before writing code: "Environments", "Native Literals",
  "Native", "Include", "Pin".

## What the three layers have

Measured on the C of each layer (functions of SDL, SDL_image,
SDL_ttf, and SDL_mixer that it calls):

| | Functions |
|---|---|
| Pingus | 50 |
| SNKRX | 61 |
| Flare | 46 |
| The three together | 87 |
| In at least two of them | 46 |
| In all three | 24 |
| Of the 87, already in `lib/sdl.atm` | 32 |

- **All three draw into software surfaces** and then update a texture
  (`SDL_CreateRGBSurfaceWithFormat`, `SDL_BlitSurface`,
  `SDL_UpdateTexture`), besides drawing with the renderer. The reason
  is probably output identical to the originals, pixel by pixel. The
  environment must offer this path, and not only textures.
- **Only SNKRX** uses render targets, geometry, custom blend modes,
  and glyph metrics. **Only Pingus** changes the window (fullscreen,
  size, grab). **Only Flare** tints surfaces and renders UTF-8 text
  in two qualities.

They also differ in what a program sees:

| | Pingus | SNKRX | Flare |
|---|---|---|---|
| Keys | `:sdl.key.dn`, `:sdl.key.up` | `:key.dn`, `:key.up` | `:key.dn`, `:key.up` |
| Mouse | `:sdl.mouse.motion`, `.dn`, `.up` | `:mouse.mv`, `.dn`, `.up` | `:mouse.motion`, `.dn`, `.up` |
| A frame | the time, then `:sdl.draw` | `:tick`, then `:draw` | `:frame`, then `:draw` |
| Test mode | `PINGUS_FRAMES`, `_KEYS`, `_MOUSE`, `_SHOT`, `_MUTE`, `_FPS` | `SNX_FRAMES`, `_SHOT`, `_MUTE`, `_SCALE`, `_RENDER`, `_PROFILE` | its own |

## Settled decisions

The author decided these. The items marked "(confirm)" are
recommendations that he has not answered: ask, one at a time, before
building on them.

- **Repository**: `ia-atmos/env-sdl`, commits straight to `main`, in
  small grains, pushed as you go. No other branch, no pull request.
- **One environment for the three games**, in this repository.
- **What is of a game stays in the game**: the ground maps of Pingus,
  the physics of SNKRX, the pathfinding, the collision, and the maps
  of Flare. Only the platform moves here: the window, the input, the
  images, the surfaces, the text, the sound, the time, the test mode.
- **The games move one at a time, Pingus first**, each with its own
  tests identical before and after. Each game is moved by its own
  session, in its own repository; this session writes the
  environment and helps.
- **One file at the root** (confirm): `sdl.atm`, with its functions in
  one table `sdl`, as `raylib.atm` and `pico.atm`. It starts as
  `lib/sdl.atm` of the compiler.
- **The names of the events have no prefix**: `:key.dn`, `:draw`,
  not `:sdl.key.dn`. The author decided it for all environments on
  2026-11-13. The names and the fields themselves are not settled
  (item 46 of the list of the compiler; the recommendation there is
  the vocabulary of `pico.atm`): write the tags in one place of the
  file, so that they are easy to change.
- **One test mode** (confirm): one set of variables for the three
  games, after those of `lib/sdl.atm` (`SDL_ATM_FRAMES`, `_KEYS`,
  `_SHOT`), with the mouse of Pingus added.
- **`lib/sdl.atm` leaves the compiler** (confirm), when this
  repository has it and its tests; `exs/rocks/` of the compiler then
  needs a home (a repository `sdl-rocks`, as in the original
  organization, or an example here).
- **How a game gets the environment** (confirm): a checkout at a
  fixed commit, made by the setup script of the game, as the games do
  with the compiler. Not a copy inside the game.
- **Documents in English**; talk to the author in Portuguese.

## Method

1. **Inventory first, no design yet.** For each of the three layers,
   list every function and event that its game calls, and classify
   it: platform and common; platform and of one game; of the game
   (stays). Record the SDL calls behind each. This is a document,
   `doc/inventory.md`, and it decides the interface.
2. **Design the interface from the inventory**: the smallest set that
   serves the three. Where two games do the same thing in two ways,
   choose one and say which game changes. Show the design to the
   author before writing it.
3. **Grow `sdl.atm`** in small steps, each with a test.
4. **Move Pingus**, with its session. Then SNKRX, then Flare. A game
   may need something the environment lacks: add it here, with a
   test, and not in the game.

## Fidelity

- **This repository**: tests with no screen (`SDL_VIDEODRIVER=dummy`),
  with fixed frames and scripted input, that compare traces and
  screenshots. Every function has one. Build them with
  `ATMOS_ASAN=1` too.
- **Each game**: its own suite must give the same traces and the same
  screenshots after it moves. Pingus has 159 traces; SNKRX and Flare
  have theirs. A difference is a defect of the move, never an
  accepted variation.
- **The software path**: where a game depends on the exact pixels of
  a surface, the environment must reproduce them. Check the
  screenshots of the games, not only their traces.

## What the other ports taught

Read "What the Pingus port taught" in `ia-atmos/lang`,
`.claude/plans/261111-snkrx.md`, and the two bindings above. For an
environment in particular:

- **A native literal fails by assigning to `st`**:
  `` `if (bad) { st = a_error("x"); }` ``. Never `return` out of one.
  So the functions of the environment may be Atmos functions over
  natives.
- **The names with the prefixes `a_`, `A_`, and `atm_` are
  reserved.** Give every name of the prelude a prefix of your own.
- **A resource is a native box with a finalizer** (`a_nat`). At the
  end, call `atm_stop()`, then `atm_quit()`, and only then
  `SDL_Quit()`: the finalizers run in `atm_quit()`.
- **The time passes in pieces.** A `:clock` await awakes at each
  timer that expires, many times per frame: emit one event per frame
  for what must run once per frame.
- **A pinned value cannot be stored in a table that is an argument**
  (`f([tex=t])` with `t` pinned): design the functions so that
  resources are plain arguments.

## Risks

- **Three test modes become one.** Each game reads its own variables
  and its tests depend on them. The move changes the scripts of the
  tests, not only the code.
- **The names of the events may change again**, when the author
  decides the convention for all environments.
- **A common interface that fits none.** The union of three layers
  may be worse for each than its own. If the inventory shows that a
  game needs a different model (the canvases of SNKRX), say so before
  forcing it.
- **Speed.** A layer in C called once per frame may become many calls
  from Atmos. Measure a game before and after.
